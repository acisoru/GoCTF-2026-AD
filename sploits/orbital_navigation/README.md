# АСТРОЛЯБИЯ · сплоиты

**Сервис:** `orbital_navigation` · **категория:** web-logic · **порт:** `8086`
**Где флаг:** токен владельца объекта; attack data содержит нужные для эксплуатации ID.

> Держать приватно от команд. Это reference-эксплоиты автора.

Эксплоиты оформлены как интеграционные тесты `challenges.rs` — бьют по каждой уязвимости напрямую через крейт сервиса (`orbit_ctf`). Положить файл в `services/orbital_navigation/tests/` и запустить:

```bash
cd services/orbital_navigation
cargo test --test challenges
```

## Эксплоиты

| Файл | Уязвимость | Запуск |
|------|------------|--------|
| `challenges.rs` | все шесть vuln/place | `cargo test --test challenges` |

## 1. Коллизия source ID (сообщения корабля)

**Суть.** `source_id` сопоставляется без учёта регистра, поэтому разные строки указывают на один источник.

**Эксплуатация.** `bind_source` с ID чужого корабля в верхнем регистре, затем `read_source_messages` по этому алиасу отдаёт чужие сообщения.

**Патч.** Сравнивать `source_id` как есть и привязывать источник к владельцу.

## 2. Подмена export profile (сообщения корабля)

**Суть.** Цель экспорта проверяется при создании job, но профиль остаётся изменяемым после авторизации (TOCTOU).

**Эксплуатация.** Создать job на свой корабль, затем `edit_profile` → чужой `ship_id`; `run_export` возвращает чужие сообщения.

**Патч.** Фиксировать цель в момент создания job (или запрещать правку профиля с активным job и перепроверять владельца при `run_export`).

## 3. Смешение кеша (манифест)

**Суть.** Кеш геометрии отдаёт манифест первого рейса с такой же геометрией — ключ кеша не включает владельца/рейс.

**Эксплуатация.** Создать свой рейс с той же `geometry`, что у жертвы; `report` вернёт чужой манифест.

**Патч.** Включить владельца и `flight_id` в ключ кеша.

## 4. Расширение делегированных прав (манифест)

**Суть.** При делегировании дочерний grant может получить права шире родительского.

**Эксплуатация.** Взять родительский grant (только geometry), `delegate` с `rights: ["manifest.read"]` и прочитать манифест по дочернему grant.

**Патч.** Права дочернего grant ограничивать пересечением с родительским.

## 5. SSRF (сводка)

**Суть.** `import_bulletin` ходит по переданному URL, следует за 302-редиректом на внутренний адрес и пробрасывает заголовок `X-Importer-Key`.

**Эксплуатация.** Указать свой хост, который редиректит на `/internal/summaries/<id>`; сервис прочитает чужую сводку и вернёт её содержимое.

**Патч.** Не следовать редиректам на внутренние адреса (allowlist) и не форвардить importer-key на сторонние хосты.

## 6. Подмена пакета и symlink (navigation)

**Суть.** Пакет проверяется при `approve`, но содержимое можно перезалить после; tar с symlink-цепочкой выводит чтение за пределы каталога пакета.

**Эксплуатация.** Залить безопасный пакет и `approve`, затем перезалить tar, где `attachment.txt` — symlink через `bridge` на `../../navigation/<flight_id>.txt`; `generate_report` отдаёт чужую навигацию.

**Патч.** Привязывать `approve` к содержимому (хэш), запрещать перезапись после approve и не разыменовывать symlink за пределами каталога пакета.

Публичный `flag_id` — JSON с номером place и публичным ID объекта. Токен владельца лежит
внутри authenticated encryption, ключом для которой служит сам флаг, поэтому attack data
раскрывает ID для эксплуатации, но не штатные учётные данные.

## Зависимости

Rust toolchain (`cargo`), крейт сервиса `orbit_ctf`.
